ENGINE OVERVIEW

A custom 2D game engine written in C++ from scratch, built on top of SDL2 and

OpenGL. The engine includes a full map editor, animated object editor, and a

Lua scripting layer for rapid development without recompilation.

Core Tech Stack
  • LanguageC++
  • Window/InputSDL2
  • RenderingOpenGL
  • UI (Game)TGUI (via Lua bindings)
  • UI (Editor)CEGUI
  • ScriptingLua (Raw C API)
  • NetworkingRakNet
  • DatabaseSQLite
Rendering Layers
  • Custom user-defined layers supported
  • GUI layer is always rendered on top (hardcoded)
02

LUA SCRIPTING SYSTEM

The engine exposes a Lua scripting API using the raw Lua C API (no wrappers

like Sol2 or LuaBridge). This gives full control over the Lua stack.

TGUI Lua Module

A custom Lua module was written to expose TGUI widgets to Lua scripts.

Only the commonly needed widgets are exposed. More are added as needed

(YAGNI approach).

Exposed Widgets
  • LabelStatic text display
  • RTLabelRich text label with color/italic tags via Tag system
  • ButtonClickable button with callback
  • PanelContainer widget with show/hide effects and focus support
  • ScrollablePanelScrollable container
  • EditBoxText input field with validator and password mode
  • PictureImage display widget
  • CanvasOpenGL render target embedded in TGUI
  • ListViewMulti-column list with double-click callback and data storage
  • ComboBoxDropdown selection widget
  • TabContainerTabbed panel container
Architecture Pattern

Each widget follows a 3-layer pattern:

01
cpp_* functions : Raw C++ to Lua bridge (registered via Lua C API)
↓
02
TGUI_* functions : Lua-side wrapper functions (one per cpp_* call)
↓
03
Class methods : OOP interface for use in game scripts
Tag System (RTLabel)
Rich text tags are defined globally for consistent styling

Predefined tags include stat colors: VIT, STR, DEX, AGI, INT, WIS

<color=#ff1200> ... </color> : colored text <i> ... </i> : italic text
Prompt System
A reusable Prompt class built in Lua for popup dialogs
  • Supports custom messages, multiple buttons, and input boxes
  • Buttons auto-arrange based on count
  • Show/hide with fade animation effect

FOCUS / KEYBOARD NAVIGATION SYSTEM

A custom keyboard/controller navigation system was built manually for TGUI

since it does not provide this out of the box. Motivation was SteamDeck

compatibility — players should be able to navigate all menus without a mouse.

FocusPanel Class (C++)

Manages a list of focusable Label widgets within a panel.

Key Features
  • addLabel / removeLabelRegister/unregister focusable widgets
  • getNextLabelMove focus forward (wraps around)
  • getPreviousLabelMove focus backward (wraps around)
  • changeLabelIndexJump focus by offset
  • resetLabelIndexReset to first widget
  • getType()Bitmask — 1 = has Panel, 2 = has Gui
Internal Data
  • std::vector for ordered navigation
  • std::set for O(1) duplicate checking on add
Focus Stack (TGUIScriptingManager)

A vector acting as a priority list of active FocusPanels.

  • NOT a true FILO stack
  • When a panel gains focus, it moves to the front
  • Other panels preserve their relative order
  • m_savedFocusPanel maps Panel pointers to their FocusPanel objects
Lua Side
  • ControlHandler_AddFocusableWidget(host, widgetPtr, parentPtr)
  • ControlHandler_reciever_push(host, panelPtr)
  • ControlHandler_reciever_remove(host, panelPtr)

GAME PROJECT — TOUHOU TURN-BASED (MULTIPLAYER)

A multiplayer turn-based RPG using Touhou Project characters.

Inspired by Darkest Dungeon (party management) but with a 3x3 grid formation

system instead of a linear 1x4.

Tech Stack (Game)
  • EngineCustom (above)
  • NetworkingRakNet
  • UITGUI via Lua
  • ScriptingLua
  • DatabaseSQLite3
// BATTLE SYSTEM DESIGN
Formation
  • 3x3 grid per player (9 cells total)
  • Max 4 characters placed per player
  • Empty cells enable: Summon and Invisibility mechanics
  • Cell position affects available skills
Attack Types
  • MeleeCan only target the front-most enemy in a column
  • RangedCan reach any row
  • AOEHits the target cell + adjacent cells
Turn Order
Each round, effective speed is calculated per character
  • Speed ties are resolved by reroll
  • Turn queue is broadcast to both players for transparency
effectiveSpeed = baseSpeed + agilityBonus + itemBuffs + diceRoll(1~6)
Match Length
  • Target: 7 to 15 rounds
  • No turn limit
  • Ends when one side is fully wiped or a player concedes
// CHARACTERS & PASSIVES
Reimu Hakurei
// passive
Fate's Favor At the start of her turn, has a (15% + missing HP%) chance to receive a random buff. Gets more dangerous as HP drops.
Patchouli Knowledge
// passive
Manashield — absorbs 80% of incoming damage, converting it to mana loss instead of HP loss. Counter: mana drain.
Hong Meiling
// passive
"Liang Yi Zhuang" Stance System — unique stance mechanic that boosts physical attack or defense based on selected stance. Stance switch is a free action (does not cost her turn).
Yukari Yakumo
// passive
Fate Reflection — when targeted, has a 17% chance to reflect the attack to a random cell on either field (including her own side).
Remilia Scarlet
// passive
Fate Manipulation — on a failed dodge or missed attack, gets a second roll at a reduced chance. Abuses the RNG layers of the game more than any other character.
